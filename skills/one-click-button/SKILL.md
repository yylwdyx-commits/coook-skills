# 把脚本做成一个按钮

## 先判断该不该做
满足前两条就该做成按钮：
1. 要追的事件发生得少，但时刻不可预测（月度账单哪天几点出不一定）——定时任务追它要么慢，要么白跑很多次。
2. 人本来就会在那个时刻出现（听说出账单了就去看）——人到场就是最准的触发信号。
3. 跑一次代价不低（要开浏览器、要登录、有风控）。
高频连续的数据、没人会主动看的对账、必须到点就新的日报告警，老老实实定时。

## 链路
按钮 → 后端接口（自己做鉴权）→ 立即返回任务 id，后台起子进程跑脚本 → 页面每 2 秒查一次状态 → 跑完刷新数据。
- **只加开关，不重写管线**：脚本怎么写数据、日志去哪，全部沿用原来的。
- 页面上「上次更新时间」必须和按钮放在一起，不然人会以为数据自己会变新。

## 稳的细节
- 单实例：已经有一趟在跑，就返回那一趟，别重复发车。
- 必须有超时：卡死就杀掉，否则按钮永远不可用。
- 执行端加锁（`mkdir` 原子锁），并且锁超过 N 分钟自动回收，避免一次崩溃把按钮永久堵死。
- 跨机器触发时，给发起端一把**只能干这一件事**的钥匙：`authorized_keys` 里写 `restrict,command="/绝对路径/trigger.sh" ssh-ed25519 ...`，脚本里不读 `$SSH_ORIGINAL_COMMAND`；装完用 `ssh ... id` 验证，输出应是脚本结果而不是 uid。
- 撤定时任务要可回滚：配置文件改名留着，不删；写清怎么恢复。如果下游有人默默依赖数据是新的，就只加按钮、不撤定时。
