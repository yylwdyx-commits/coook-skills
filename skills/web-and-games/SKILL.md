# 做网页和小游戏

## 默认做法
1. **一个 index.html 跑通**：CSS、JS 内联，不引外部字体、脚本、图片（除非用户明说要）。图标和插画用 SVG 或 CSS 画。双击就能打开，断网也能用。
2. **先做能动的第一版，再打磨**：先让核心玩法/核心区块跑起来并落盘，再加动效、音效、细节。时间不够时交付的是能用的东西，不是半截的漂亮东西。
3. **手机和电脑都要好看**：`<meta name="viewport">`、弹性布局、触摸事件和键盘事件都接上；手机宽度（390px）下不能出现横向滚动条。
4. **游戏类**：用 `requestAnimationFrame` 驱动，按真实时间步长算物理（不按帧数），有开始、暂停、结束、重新开始；分数和最高分存 localStorage。
5. **给自动化测试留钩子**：用户提到测试，或玩法有规则可验证时，在 `window.game` / `window.app` 上暴露读状态、设状态的函数。

## 交付前自己验一遍（必做）
- 用真浏览器打开页面：控制台零报错、没有加载失败的资源、画面真的在动。
- 看截图，不只看文字结论：布局有没有塌、字有没有被挡、颜色对不对。
- 分别用电脑宽度和手机宽度各看一次。
- 有规则的玩法（消除、合并、碰撞、计分）挑一两个边界情况真点一遍，比如 2048 的 [2,2,2,2] 左移应得 [4,4,0,0]。
- 验不过就改，改完再验；只说「应该可以了」不算完成。

## 常见坑
- 字体：别用 Google Fonts 等外链；中文用系统字体栈 `-apple-system, "PingFang SC", "Microsoft YaHei", sans-serif`。
- 画布模糊：canvas 按 `devicePixelRatio` 放大绘制尺寸，再用 CSS 缩回去。
- 音效：浏览器要求用户先交互一次才能出声，第一次点击时再创建 AudioContext。
- 手机上 `100vh` 会被地址栏遮住，用 `100dvh`。

## 交付话术
两三句话：做了什么、怎么打开（文件路径，双击或拖进浏览器）、验证了哪些点。
