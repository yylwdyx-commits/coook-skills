# 把接口文档做成 SDK

## 流程
1. **通读接口文档**，列出：鉴权方式、每个接口的请求/响应字段、错误码、限流、回调。文档里字段名前后不一致很常见（`log_id` / `logid`），请求以示例为准，响应解析两个都认，并在文档里记一笔。
2. **先列问题清单**：文档没说清的（结算数据从哪回来、重试是否安全、时间戳单位、签名算法细节），编号列出来交给对方，别自己猜着写死。
3. **SDK 结构**：
   - `Config`：每个配置项写清取值来源（「在对方后台的 XX 页面复制」），不只给 key 名——只给 key 名，对方会自己编一个占位值。
   - `Client`：发请求 + 本地前置校验（把对方会拒绝的参数在本地先拦下，报清楚哪个字段不对）。
   - 结果对象带语义方法（`succeeded()`、`isDuplicate()`），别让调用方自己比错误码。
   - 非 200 响应把 body 带回来，不抛裸异常。
   - 依赖越少越好，目标运行环境（语言版本）按对方的来。
4. **离线自测**：不发网络，验证请求构造、签名、响应解析和错误处理，全过才打包。
5. **文档两份**：SDK 使用说明（配置表、调用示例、错误码含义、重试是否安全）+ 字段对照表（对方字段 ↔ 我方字段，写明来源）。

## 纪律
- 交付物有任何改动（哪怕只改文档）就升版本号。
- 密钥、令牌只通过安全渠道单独给，不进代码、不进文档、不进群聊。
- 只交付包和文档，不替对方往他们的代码仓库里提交。
