# 微信小程序上线

判断先行：小程序审核看的是**审核员能看到的包 + 你交的材料是否自洽**（隐私指引、类目、演示视频、测试账号、版本描述）。材料与包对不上比功能本身更容易被拒。另一条：H5 和小程序要一条主线出包，不许分叉。

## 何时用
- 新建或接手小程序，第一次上传 / 提审 / 发布。
- 被拒、线上某能力不可用（多半是隐私声明或合法域名没配）、web-view 打不开。

## 判据
- 包在**微信开发者工具里真跑**过主路径（浏览器模拟只验胶水逻辑；真运行时有只读全局、API 差异）。
- 真机预览（扫预览码）走一遍主路径并截图。
- 提审后回读后台状态是「审核中」才算提交；过审后「发布」也要回读线上版本号。
- 线上版本对应仓库哪次提交，能一条命令查到。

## 坑与真因
- **隐私保护指引按包内实际调用逐项填**：用到的接口（选图、相册、位置、手机号、好友关系…）每项写用途；没用到的从代码删掉，别空挂声明。少声明一项 → 该能力在线上直接报错（如 errno 1026 要求去后台声明）。
- **request 合法域名 / 业务域名（web-view）** 要在后台配，且需 https + 备案域名；web-view 业务域名要放校验文件到域名根目录。
- **一个邮箱只能注册一个公众平台账号**；类目一级选了不能改；个人主体不支持微信支付。
- **管理员身份验证必须证件本人的实名微信扫码**，别人代替不了，提前约好人。
- **上传者署名**：命令行（miniprogram-ci）上传，开发者一栏固定显示「ci 机器人 N」，改不了；要显示人名用开发者工具上传。开发者工具代理设「不使用代理」、打开服务端口才能被 CLI 驱动。
- **演示用的数据要先实测能出结果**：审核员照着测试账号和演示词去点，空结果 = 「功能不完整」。
- **演示视频**：手机实拍一分钟主路径，mp4 ≤20MB（转 H.264 720p）。测试账号写清登录流程。
- **包里不留调试痕迹**：内部预览浮标、调试参数、测试请求头、注释里的内部说法都清掉。
- **新功能先上 H5，小程序下一版跟**；只从主线干净提交出包，一个版本号只对应一次提交，包里带提交号；服务端接口要兼容线上旧版小程序。
- 小程序与网页共用后端时，后端判端别只看 UA；按请求头/参数显式区分。

## 小游戏额外要注意
- 小游戏没有 DOM：界面画在 canvas 上，按钮自己做命中检测；第一个创建的 canvas 才上屏。
- 真运行时有只读全局（例如给 `GameGlobal.document` 赋值会抛错导致黑屏），赋值前先判断是否已存在；浏览器里模拟的运行时测不出来，上传前必须在开发者工具真跑。
- 有开放数据域时，上传开「压缩/增强编译」可能编译失败，关掉再传（注意包体上限）。
- 小程序自动化测试库多半不支持小游戏，别在上面耗时间。
- 好友排行、选图、存相册这类能力要在隐私保护指引里声明，否则线上调用直接报错。
- 纯单机（无自有服务器）通常只需做小游戏备案；游戏类目要自审声明，素材（配乐、主角图）先确认是原创或已获授权再签声明。
- 广告：激励视频只给真实奖励，插屏避开启动和刚看完激励的时段，分享不给奖励（诱导分享会被处罚）。

## 检查清单（提审前）
1. 开发者工具真跑 + 真机预览，主路径截图。
2. 隐私保护指引 = 代码实际调用的接口集合（多一个少一个都不行）。
3. 合法域名、业务域名、校验文件就位；域名已备案、https 有效。
4. 版本描述三条讲清做什么；测试账号 + 登录步骤；演示视频；演示数据实测有结果。
5. 联系电话等主体信息是主体本人的。
6. 包内无调试痕迹；包里写入提交号；版本台账记一笔。
7. 提审后回读状态；过审发布后回读线上版本。
