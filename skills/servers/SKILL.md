# 管多台电脑和服务器

## 上机
- **只用密钥登录**，不用明文密码；在 `~/.ssh/config` 里给每台机器起名字（Host 别名 + HostName + User + Port + IdentityFile），以后 `ssh 名字` 一步到位。
- 每台机器写清「首选路径 → 备用路径」（公网直连 / 跳板 / 内网穿透 / 组网工具）。
- 长任务不要挂在一条 ssh 上：`nohup 命令 > 日志 2>&1 &` 后台跑，再读日志。
- 重的活放算力够的机器，一次一件；生产机器别并发压死。

## 连不上：先分故障域，再动手
1. **先验本体，再信监控**：告警说 X 挂了，先直接探 X（登录、请求真实页面），本体活着而看板是红的 = 病在监控。
2. **三分法定性**：ping 不通 = 整机或网络；TCP 握手通但不回数据（ssh 没有 banner、网页一直转）= 进程被压死或卡住，查内存和负载；数据也正常 = 问题在上层（证书、配置、权限）。
3. **多点对照**：换一个网络、换一台机器测同一个目标——「只有这里坏」和「到处都坏」是两种病，十秒钟就能分清。
4. **常见骗局**：多台机器「同时」掉线，多半是共用的那段路（网关、跳板、代理）断了，不是机器都挂了；域名解析怪，先用公共 DNS 再解析一次（`dig 域名 @公共DNS地址`），和本地结果对比，可能是 DNS 污染。
5. **别快速重试硬撞**：密集重试可能被防火墙当成攻击，把自己封掉。退避 10 秒以上，总共不超过 3 次。
6. 没拿到机器里的证据（日志、`dmesg`、负载）之前，结论只能说「疑似」。

## 回报
先答「通 / 断 / 正在自愈，大约几分钟后好」，再给故障在哪一层、证据（带时间）、做了什么。看到真实业务恢复（页面能打开、心跳恢复）才说好了。
