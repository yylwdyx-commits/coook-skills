# 做 Word / PPT / Excel

## 工具选择
- Python 有 `python-docx` / `python-pptx` / `openpyxl` 就用它们；没有就 `pip install --user` 装上（装不上再考虑 Node 的 docx / pptxgenjs / exceljs）。
- 生成代码写成脚本文件留在目录里，方便用户改了数据重跑。

## Word
- 用真正的标题样式（Heading 1/2），不要用加粗正文冒充标题——目录和导航都靠它。
- 表格最后一行是合计时，合计由代码算，不手填；交付前再算一遍核对。
- 不留「TODO」「待补充」「XXX」这类占位；信息不全就按常理写并在回复里列出「需要你确认的几处」。

## PPT
- 默认 6~10 页：封面 → 3~6 页内容 → 结尾；每页一个标题、一个要点，用短句不用大段。
- 数字尽量做成图表（python-pptx 的 chart）或表格，数字必须和原始材料一致。
- 版式：16:9；正文字号不小于 18pt；所有元素不出页面边界——生成后用代码检查每个 shape 的 left/top/width/height。
- 想要更好看的效果，可以先用 HTML 做页面、截图后铺满幻灯片；但这样文字不可编辑，要先跟用户说明。

## Excel
- 表结构照用户说的来：说「每人每周一行」，那张表就只有这些数据行。明细表不加合计/小计行（哪怕隔一行也不加），合计放汇总表或在回复里说——明细要留给用户排序、筛选、透视和公式引用。
- 能用公式就写公式（`=SUM(...)`），不要把算好的数写死；同时检查公式结果对不对（openpyxl 不算公式，用 Python 自己算一遍对照）。
- 表头冻结、列宽合适、金额列用千分位格式、日期用日期格式。
- 有个税、社保这类规则时，把规则写成参数表放在单独的 sheet，别埋在公式里。

## 交付前自检
- 用代码重新打开生成的文件读一遍（能打开、页数/行数对、关键数字对）。
- 能转 PDF 就转一份（`soffice --headless --convert-to pdf`），截图看版面。
- 回复写：文件路径、每页/每节讲了什么、需要用户确认的地方。
